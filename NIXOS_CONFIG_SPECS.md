# NixOS Config Project Specifications

This document records the requirements and specifications for this repository's NixOS configuration.
It serves as a reference for future maintenance and extension.

## General Purpose

Provide a usage experience similar to Fedora Silverblue or the Bluefin project, with:

- A lean, declarative base system via Nix Flakes
- GUI applications installed preferentially via Nix; Flatpak only for apps with no nixpkgs equivalent
- An ephemeral system (preservation) with a clean root on every boot
- Important data preserved in dedicated Btrfs subvolumes

## Composition Architecture

- The flake uses flake-parts with a dendritic pattern.
- Every non-entrypoint Nix module relevant to high-level composition lives under `dendritic/`.
- The host and user inventory is centralized in:
  - `dendritic/data/hosts.nix`
  - `dendritic/data/users.nix`
- The flake outputs are generated by dedicated modules:
  - `dendritic/flake/nixos-configurations.nix` — generates `nixosConfigurations.<host>`
  - `dendritic/flake/disko-configurations.nix` — generates `diskoConfigurations.<host>`
  - `dendritic/flake/home-nixos-module.nix` — wires Home Manager as a NixOS
    module for every user (there's no standalone `homeConfigurations` output;
    HM is applied together with `nixos-rebuild switch`)

## Disk Partitioning

### Requirements

- UEFI support
- Full-disk encryption via LUKS + LVM
- Declarative partitioning via nix-community/disko
- Btrfs filesystem for the main partition
- Hybrid swap: zram (performance) + disk swap (hibernation)
- Ephemeral system via nix-community/preservation

### Partition Layout

```text
Disk (e.g. /dev/nvme0n1)
├── Partition 1: ESP (512 MB, FAT32)
│   └── Mountpoint: /boot
└── Partition 2: LUKS (rest of the disk)
    └── LVM VG: root_vg
        ├── LV swap: 20 GB
        │   └── Swap (for hibernation)
        └── LV root: 100%FREE
            └── Btrfs
```

### Ephemeral root (tmpfs)

The system root (`/`) is a **tmpfs** — an entirely RAM-backed filesystem. This means:

- It's always clean on every boot (no accumulated data, no rollback needed)
- Any file written to `/` is lost on reboot (except what's preserved under `/persist`)
- Simple and reliable: no snapshot, rollback or initrd configuration required

**Mount options:** `defaults,size=50%,mode=755`

### Btrfs subvolumes

The `@` convention is compatible with tools like Timeshift and widely adopted by the community.

| Subvolume | Mountpoint | Characteristics |
| --------- | ---------- | --------------- |
| `@home` | `/home` | Preserved — user directories |
| `@nix` | `/nix` | Preserved — Nix store (essential) |
| `@persist` | `/persist` | Preserved — persistent system data (preservation) |
| `@log` | `/var/log` | Preserved — system logs (no compression) |
| `@containers` | `/var/lib/containers` | Preserved — container data |
| `@flatpak` | `/var/lib/flatpak` | Preserved — Flatpak apps |
| `@snapshots` | `/.snapshots` | Preserved — Btrfs snapshots for backup |

**Global mount options:**

- `compress=zstd` (except `@log`: no compression)
- `noatime`

**Preservation strategy:**

- The tmpfs root is always "clean" on boot — no snapshot or rollback needed
- Important files are preserved in `/persist` via bind mounts (preservation)
- `/persist` is a Btrfs subvolume persistent across boots

### Hybrid Swap

**Per host (16 GB RAM):**

| Component | Size | Priority | Purpose |
| ---------- | ------- | ---------- | -------- |
| zram (zstd) | 8 GB (50% RAM) | 100 (primary) | Everyday performance |
| Disk swap | 20 GB | 5 (backup) | Hibernation |

**Behavior:**

1. The system uses zram first (faster, doesn't wear the SSD)
2. When zram is exhausted, it uses disk swap
3. Hibernation uses disk swap

## Home Manager

- Used as a NixOS module (`home-manager.nixosModules.home-manager`), integrated into `nixosConfigurations`
- Shares the same system nixpkgs (`useGlobalPkgs = true`), inheriting the overlay and allowUnfree
- User packages installed in `/etc/profiles/per-user/<user>` (`useUserPackages = true`)
- Base configuration in `home/common.nix`
- Per-user configuration in `home/users/<user>/home.nix` (when needed)
- Automatic wiring in `dendritic/flake/home-nixos-module.nix` from the dendritic inventory

## Preservation (Ephemeral System)

### How It Works

1. The system root (`/`) is a **tmpfs** — a RAM-backed filesystem, always empty on boot
2. No rollback, snapshot or initrd service is needed
3. Important files and directories are preserved via bind mounts from `/persist`
4. `/persist` is a persistent Btrfs subvolume (survives any number of reboots)
5. `/home`, `/nix`, `/var/log`, `/var/lib/containers` and `/var/lib/flatpak` are also persistent Btrfs subvolumes
6. Implemented via `nix-community/preservation` (the `preservation.preserveAt."/persist"` module)

### Automatically Preserved Data (System)

- `/etc/nixos` - NixOS configuration
- `/etc/NetworkManager/system-connections` - Network connections
- `/var/lib/systemd` - systemd state
- `/var/lib/nixos` - NixOS internal state
- `/var/lib/bluetooth` - Bluetooth devices
- `/var/db/sudo` - sudo timestamps
- `/etc/machine-id` - Unique machine ID
- Server SSH keys (configured in ssh.nix)

### Per-User Preserved Data (template)

- `~/Downloads`
- `~/Documents`
- `~/Pictures`, `~/Videos`, `~/Music`
- `~/.ssh`
- `~/.gnupg`
- `~/.local/share/keyrings`
- `~/.config/gh`
- `~/.local/share/flatpak`
- `~/.var/app`
- `~/.local/share/containers`
- Bash and Zsh history

## Security

### LUKS

- AES-256 encryption by default
- `allowDiscards = true` for better performance on SSDs
- Password prompt at boot via Plymouth as a fallback

### TPM2 (Automatic LUKS Unlock)

- Module: `modules/system/security/tpm2.nix`
- Enabled by default on all hosts
- Uses `systemd-cryptenroll` to bind the LUKS key to the TPM2
- PCRs checked: 0 (UEFI firmware) + 2 (UEFI option code) + 7 (Secure Boot state)
- Automatic fallback to manual password if the PCRs change
- Included tools: `tpm2-tools`, `tpm2-tss`
- Kernel modules loaded in the initrd: `tpm_tis`, `tpm_crb`
- **Requires manual enrollment after installation** (see INSTALLATION.md)

### Secure Boot (barbudus)

- Implemented via Limine (`boot.loader.limine.secureBoot`), without shim/MOK
- PKI keys stored in `/persist/etc/secureboot` (symlinked from `/var/lib/sbctl`)
- The firmware verifies the signature of the Limine binary; kernel/initrd are
  verified via a BLAKE2B checksum embedded in the enrolled `limine.conf`

### SSH

- Password authentication disabled by default
- Root login disabled
- Server keys at `/persist/etc/ssh/`
